# Admin visitor counts

The admin dashboard shows **Live visitors** (unique browser IDs with a heartbeat in the last 120 seconds) and **Total visitors** (unique browser IDs since installation). Refreshes, SPA navigation and multiple tabs share the existing first-party `az_sid` identifier. Different devices, private browsing, cleared storage and blocked tracking can change counts. Known crawler/preview user agents, admin routes/hosts, hidden tabs, Do Not Track and Global Privacy Control are excluded. These are browser-based estimates, not an exact count of people, and cannot recover earlier untracked marketing visits.

The storefront sends an optional heartbeat every 45 seconds while visible, with a five-second timeout. Nothing waits for it during rendering or checkout. The admin reads aggregate counts every 15 seconds while visible, with an eight-second timeout and slower retries when unavailable. Existing counts remain visible during a failed update instead of being replaced by zero. The dashboard does not display visitor identifiers, addresses or names.

PHP `/api/visitors` runs before `az_open()`, so marketing traffic never takes the orders database lock or triggers its backups. Counts use separate storage under `RUNTIME_DIR/visitors`, with nonblocking registration/log locks. Anonymous identifiers are hashed, unique IDs are split across 256 files, and short-lived minute logs are capped at 2 MB each and pruned. Unique registrations use an atomic recovery journal so interrupted writes do not double-count. PHP and the single-process Node server share the same storage format. No paid service, external tracking script, IP storage or database extension is needed. Storage problems fail only the optional tracker; private count reads report unavailable.

Deploy the backend before the frontend: `php/visitors.php`, `index.php`, `php/api.php`, `lib/visitors-store.mjs`, `lib/routes/visitors.mjs`, then `public/js/features/visitors.js`, `public/css/features/visitors.css`, `public/js/features/policies.js` and finally `public/js/features/index.js`. No order-data migration or reset is required. Do not deploy the unrelated AI try-on work as part of this change.

Checks: `node tests/visitors.test.mjs`, `node tests/storefront-regressions.mjs`, and `node tests/php-smoke.mjs` with PHP 8.2+ (or `PHP_WASM_MODULES` pointing to the existing PHP WASM installation). Verify both the storefront and admin hostname after deployment. Public `POST /api/visitors` must return an acknowledgement, while counts at `GET /api/admin/visitors` require the normal admin credentials and are never cached. Totals start with the first accepted heartbeat.
